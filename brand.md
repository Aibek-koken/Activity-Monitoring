# Brand — EasyLang Activity Monitoring

_Status: active_

## Direction

EasyLang should feel calm, precise, and operational. The interface is a professional working tool for translators, chief editors, and project managers, not a marketing site. Screens should stay compact and avoid roadmap, test, or implementation-status language in the product UI.

The visual references in `Project_3_Task_3_Final.pdf` are inspiration only. The product UI may use a different composition as long as it keeps the same light, restrained character and a similar green-teal accent.

## Color system

- Primary: deep slate blue (`--primary: 215 36% 25%`)
- Primary hover: darker slate blue (`--primary-hover: 215 39% 19%`)
- Brand accent: restrained teal (`--brand: 170 55% 37%`)
- Soft accent: pale teal (`--brand-soft: 169 44% 92%`)
- Canvas: cool off-white (`--background: 215 36% 97%`)
- Text: deep slate (`--foreground: 215 35% 16%`)
- Semantic colors are reserved for success, warning, and error states.

All application code must consume semantic CSS tokens rather than inline color values. The current product direction intentionally uses a consistent light theme.

## Typography

Use Inter with system fallbacks for a clear, compact interface. Headings are confident but not oversized. Numeric monitoring data should use tabular figures.

## Voice

Use direct, calm language. Explain what happened and what the user can do next. Avoid vague labels and technical error messages.
